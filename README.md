# BAS-IP Manager
Данный проект нацелен на создание единого центра управления дверьми, поддерживающими API интерфейс BAS-IP.
В общем проект представляет из себя Систему Управления Интернетом Вещей, направленную на удаленный контроль продуктами, разработанными BAS-IP.

Реализация предполагает разделение на 2 приложения:
- `"agent"` (agent):
    Развернутое в пространстве, имеющем прямой доступ к продуктам от BAS-IP, веб-приложение (backend сервер), собирающее состояние данных продуктов и имеющее возможность отправить им команду на безусловное временное открытие замков. Общается с сервером Управления, устанавливая с ним стабильное соединение через протокол WebSocket.
- `"server"` (management):
    Сервер, аутентифицирующий агентов и устанавливающий с ними WebSocket соединение, в рамках данного соединения имеет возможность разослать агентам команду на инициализацию процесса открывания замков. Взаимодействие с данным сервером конечным пользователем осуществляется через REST API.

## Агент
При запуске агент обязательно должен потребовать от администратора, запускающего его, путь до файла конфигурации с информацией о дверях (интерфейсах электронных замков), находящихся в рамках доступной данному агенту сети.
### Шаблон конфигурации дверей (интерфейсов электронных замков):
```yaml
panels:
  front-door:
    address: 192.168.5.6
    username: user
    password: pass
```

## Задачи
**Ожидают скорейшей реализации фичи**:
- API Client для API-интерфейса BAS-IP:
    - (1) в src создать модуль `clients`, в котором нужно реализовать класс REST API клиента со всеми необходимыми методами для работы с продуктами BAS-IP:
        - (2) логин
        - (2) открытие двери
        - (3) провести ресерч по тому, какие еще методы необходимо реализовать для более комфортной работы с продуктами
- Чтение конфигурации дверей:
    - в entrypoint агента `agent.py` реализовать требование по передаче аргумента/опции, в которой будет храниться путь до конфигурации дверей
    - реализовать DTO класс, предоставляющий хранение конфигурации
    - (4) реализовать метод, позволяющий создать API Client на основе одной из конфигурации для конкретной двери (не для всех сразу, а для одной из записей)
- Реализация командного интерфейса в рамках WebSocket подключения (скорее всего придется переписать класс `WebSocketClient`):
    - по сути в websocket мы должны уметь читать 2 разные команды:
        - (1) heartbeat / healthcheck
        - (5) "открыть двери"
    - (2) надо провести code review и возможно немного подправить точку входа для `WebSocketClient`, чтобы он мог начинать свою работу ТОЛЬКО когда мы аутентифицировались в management
- Реализация аутентификации в management сервере сразу при запуске:
    - (1) реализовать логику, при которой как только агент стартовал, он пытается произвести аутентификацию в management сервере с имеющимися у него ключами
    - (3) при успешной аутентификации агент должен открывать вебсокет соединение и становитсья доступным для heartbeat и других команд от management сервера
- (6) REST API эндпоинт для открытия дверей на стороне management сервера:
    - добавить поддержку контроля неограниченного количества websocket соединений
    - реализовать REST API эндпоинт, при успешном обращении на который management сервер броадкастит команду на открытие дверей на все свои websocket соединения своим агентам
